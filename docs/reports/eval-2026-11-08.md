# Full eval run, 8 November 2026

`npm run eval:suite -w @tv/server` across all 100 cases, Swarms off, cache off.

## Result

The run printed 46/100, but most failures came from Gemini quota, not from the designs.

| | Cases |
|---|---|
| Passed | 46 |
| Failed because Gemini was out of quota (one call, "the design step failed", or local rules refusing) | 39 |
| Real failures, with a working Gemini | 15 |

Of the 61 cases that had a working Gemini, 46 passed (75%). The earlier strict run passed 57 of 57.

## Why the real failures happened

- **Repairs ran on the weaker model.** Repairs use `gemini-3.5-flash`, which wires logic far better, but the free tier allows it 20 requests a day. Of 81 repairs in this run, 9 used flash and 72 fell back to `gemini-3.5-flash-lite`. Most real failures are classic electronics circuits that need a good repair: the robot car, thermostat, 555 traffic light, 7-segment decoder, flip-flop, fan, Pico light and op-amp buffer.
- **Two block cases failed for code reasons, now fixed (6027ccb):** the ALU design added its own copies of the block's LEDs and switches, and the comparator design most likely gave its block an id with an underscore. Both pass on rerun.
- **Fleet:** two search missions (rovers, ants) found targets but never reported them, because the finder was out of radio range.

## Core code is not the cause

All 88 shipped verified designs were re-validated on current code: 87 pass, and the 88th is the deliberate "LED straight to a 9 V battery" demo, which is meant to burn out. The solver, coverage check, blocks and layout changes broke no known-good circuit.
